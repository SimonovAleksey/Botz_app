# Рабочие заметки — Robot Controller App

## Файлы проекта
- `MainWindow.h / .cpp` — весь UI (меню, tank, steering, анимации)
- `network/WebSocketClient.h / .cpp` — TCP сервер (QTcpServer), ждёт подключения от ESP32
- `controllers/RobotController.h / .cpp` — прослойка между UI и сетью
- `robot_esp32/robot_esp32.ino` — прошивка ESP32 (TCP клиент)
- `CMakeLists.txt` — сборка Qt6

## Что сделано

### Фронтенд (Qt6)
- [x] macOS-стиль: SF Pro шрифт, белые карточки, тени, скругления
- [x] Экран меню: поле IP + кнопка Connect, статус, карточки режимов
- [x] Tank режим: два вертикальных слайдера (LEFT/RIGHT), кнопки Light/Extra
- [x] Steering режим: вертикальный throttle + горизонтальный steering
- [x] Клавиатурное управление: W/S, ↑/↓, A/D, L, E, Escape
- [x] Плавный возврат слайдеров в ноль после отпускания
- [x] Фикс: слайдер не дёргается пока удерживается мышью (heldSlider)
- [x] Подсветка слайдера цветом при движении (glow на карточке)
- [x] Кнопки Light/Extra с анимацией свечения при включении
- [x] Зелёная вспышка окна при подключении, красная при ошибке
- [x] Статус "Waiting for robot..." когда сервер запущен но плата не подключилась
- [x] IP поле становится read-only и показывает адрес сервера после Connect
- [x] Виджет заряда батареи в заголовке Tank/Steering (🔋 %, В), цвет зелёный/жёлтый/красный
- [x] Сбрасывается при отключении робота
- [x] Заголовки карточек "Танковое управление"/"Рулевое управление" в главном меню — включён `setWordWrap(true)` у QLabel, текст переносится по словам в пределах ширины карточки (172px)
- [x] Подсказка "как узнать IP компьютера" (кнопка "?" на экране Program Board) — добавлена инструкция и для Windows (Параметры → Сеть и Интернет → Wi-Fi → Свойства → IPv4, либо `ipconfig`), не только для macOS
- [x] Фикс: при уменьшении окна цифры под слайдерами в Tank-режиме налезали на сами слайдеры — `setMinimumSize` поднят с (680,460) до (680,600), `resize()` по умолчанию с (820,560) до (820,620)
- [x] Фикс мигания кнопок Light/Extra: при первом же переключении на кнопку навешивается `QGraphicsDropShadowEffect` (для анимации свечения) и остаётся висеть на ней даже после выключения (просто с blurRadius=0). При каждом следующем открытии экрана Tank/Steering этот "висящий" эффект конфликтовал с собственным fade-in эффектом экрана (`QGraphicsOpacityEffect` в switchTo()) — кнопка на один кадр отрисовывалась в неправильном месте, потом резко вставала на место. Исправлено: после анимации выключения (blur → 0) эффект полностью снимается с кнопки (`btn->setGraphicsEffect(nullptr)`), отложенно через `QTimer::singleShot(0, ...)`, чтобы не удалять объект эффекта изнутри его же сигнала `finished`

### Бэкенд (WebSocket)
- [x] Переход QTcpServer → QWebSocketServer (Qt6::WebSockets)
- [x] Mac = WebSocket сервер (порт 8080), ESP32 = WebSocket клиент
- [x] ESP32-клиент написан вручную по RFC 6455 поверх WiFiClient (без сторонних библиотек)
- [x] Handshake: HTTP GET + Upgrade: websocket, проверяем "101" в ответе
- [x] Чтение кадров: text/continuation + автоответ на ping (pong) + обработка close
- [x] JSON-сообщения передаются как WebSocket text frame
- [x] ESP32 переподключается каждые 3 сек если нет соединения
- [x] Двунаправленный канал: ESP32 → Mac тоже шлёт текстовые кадры (battery), RobotController парсит входящий JSON и эмитит batteryUpdated(voltage, percent)

### ESP32 прошивка
- [x] Убрана зависимость от TB6612_ESP32.h — прямое управление через LEDC PWM
- [x] Переход на новый API ESP32 core 3.x: ledcAttach() вместо ledcSetup()+ledcAttachPin()
- [x] Нет сторонних WebSocket-библиотек — только WiFi.h + ArduinoJson + Adafruit_NeoPixel
- [x] WiFiClient (TCP) + ручной WebSocket-протокол RFC 6455
- [x] Автореконнект к Mac каждые 3 секунды
- [x] Debug-светодиод (GPIO2, встроенный на плате) — горит при изменении значений из приложения, гаснет если изменений нет 300мс (полезно тестировать без подключённых моторов)
- [x] Подробный лог [TANK]/[STEER] в Serial при изменении значений (не на каждый keep-alive)
- [x] Отправка заряда батареи (GPIO34/ADC1_CH6) каждые 2 сек: {"type":"battery","voltage":..,"percent":..}
- [x] Батарея — упрощено: 3.3В на пине ADC = 100%, без делителя/калибровки (BATTERY_DIVIDER_RATIO, BATTERY_MIN_V/MAX_V и инструкция по калибровке удалены из .ino)

### Упаковка / дистрибуция
- [x] macOS: CMakeLists.txt → `add_executable(... MACOSX_BUNDLE ...)`, получаем настоящий `.app` вместо голого бинарника
- [x] macOS: `macdeployqt RobotControlApp.app -dmg` подкладывает Qt-фреймворки внутрь бандла
  - ⚠️ macdeployqt после копирования ломает codesign-подписи скопированных Homebrew-библиотек (например libbrotlicommon) → приложение мгновенно убивается Gatekeeper'ом (exit 137) при запуске из .dmg
  - Фикс: `codesign --force --deep -s - RobotControlApp.app` (ad-hoc подпись) после macdeployqt, до сборки финального .dmg
- [x] Финальный .dmg собран вручную через `hdiutil create` из staging-папки с `.app` + symlink на `/Applications` (macdeployqt сам не добавляет ярлык на Applications)
- [x] Windows .exe: честная локальная кросс-компиляция с Mac (mingw-w64 + Qt6 собранный из исходников под Windows-target) признана нецелесообразной — слишком долго (1–3+ часа) и ненадёжно из-за возможных ABI-несовпадений
- [x] Решение — собрать .exe через GitHub Actions (репозиторий пользователя SimonovAleksey/Botz_app):
  - добавлен `.github/workflows/build-windows.yml` (runs-on windows-latest, `jurplel/install-qt-action` ставит Qt 6.7 + модуль qtwebsockets, CMake+MSVC сборка, `windeployqt` подкладывает DLL, всё упаковывается в zip-артефакт)
  - в репозитории уже был git remote с Personal Access Token прямо в URL (`.git/config`) — секрет в открытом виде, пользователя предупредили, что токен стоит ротировать после задачи
  - первый push workflow-файла был отклонён GitHub: "refusing to allow a Personal Access Token to create or update workflow ... without `workflow` scope" — старый токен не имел права `workflow`
  - пользователь выпустил новый токен с правами repo+workflow, remote обновлён (`git remote set-url`), push прошёл успешно
  - сборка запущена через GitHub API (`POST .../actions/workflows/build-windows.yml/dispatches`), т.к. `gh` CLI не установлен и интерактивный `gh auth login` не подходил
  - статус сборки опрашивался через REST API в фоновом Bash-процессе; первая попытка мониторинга упала с ошибкой `status: read-only variable` (в zsh `status` — зарезервированное имя переменной), исправлено переименованием в `run_status`
  - готовый артефакт (`RobotControlApp.exe` + все нужные Qt6 DLL: Core/Gui/Network/Widgets/WebSockets/Svg + плагины) скачан через API и сохранён на Десктоп: `~/Desktop/RobotControlApp-windows.zip` (~22 МБ), готов к передаче другу

## Что не сработало
- ❌ QWebSocket — Qt не смог подключиться к ESP32 WebSocketsServer
- ❌ QTcpSocket с bind() к en0 — VPN (utun6) перехватывал пакеты на уровне ядра даже при явной привязке к WiFi-интерфейсу
- ❌ sudo route add — маршрут добавлялся, но VPN всё равно перехватывал
- ❌ ESPAsyncWebServer — несовместим с ESP32 core 3.x (mbedtls ошибки, pxCurrentTCB)
- ❌ WebSocketsServer (Links2004) — линкер ошибки с ESP32 core 3.x
- ❌ Установщик Silicon Labs CP210x VCP Driver — зависал на macOS
- ❌ Bluetooth для загрузки скетча — ESP32 не поддерживает
- ❌ Полноценный билингвальный (EN/RU) UI с круглой кнопкой-флагом и пересборкой экранов на лету — реализован полностью, но пользователь попросил откатить всё обратно ("убери переключение языка, откатись..."). Причина по факту: архитектура "удалить и пересобрать виджеты экрана при смене языка" приводила к тому, что кнопки Tank/Steering мод-карточек на главном экране перестали нажиматься после переключения языка — root cause: `switchTo()` создавал fade-анимацию с лямбдой, держащей raw-указатель на `target`, без контекстного объекта в `connect()`; если виджет экрана удалялся (пересборкой при смене языка) до завершения 180мс анимации, срабатывание `finished` уже на висящем указателе. Фикс через context-object в connect() работал, но вместе с фичей был полностью откручен по явной просьбе пользователя — сейчас single-language UI, weak connect() в switchTo() безопасен только потому, что экраны больше никогда не удаляются в рантайме
- ❌ Кросс-компиляция Windows .exe прямо на Mac (mingw-w64 + Qt6 из исходников под Windows-target) — не пробовали по факту (предложили, пользователь сначала согласился, потом передумал в пользу GitHub Actions), но оценка показала, что это заняло бы часы и не гарантировало совместимость ABI

## Пожелания и замечания пользователя
- Дизайн ближе к macOS — минимализм, белые карточки, Apple шрифты
- Ползунок рулевого управления должен быть ниже
- Число под ползунком в steering должно быть зелёным (не синим)
- После отпускания ползунок не должен дёргаться
- Кнопки Light и Extra должны светиться при включении
- Окно должно мигать красным при ошибке, зелёным при подключении
- IP по умолчанию не нужен в поле ввода
- "Connection failed" → переименовать в "IP incorrect" при неверном адресе
- Нет нужды лезть в системные настройки / VPN вручную
